WEB / BUILD LOG

Rebuilding the public site around GitHub and Cloudflare

The public website source lives in the access-stack GitHub repository under a dedicated static site directory. Cloudflare Workers serves those static assets, keeping the public surface simple, inspectable and easy to deploy.

An early connected build failed until the Worker configuration was corrected with an explicit compatibility date and static-assets directory. A separate legacy Worker route was later found intercepting the public hostname; removing that route restored the intended deployment path.

The result is a clearer public structure with distinct portfolio, journal and visual-archive surfaces rather than one page carrying every responsibility at once.

VISUAL LAB / CONCEPT SERIES

Access-Stack Origins: turning project themes into a visual world

Origins is a cinematic science-fiction design exercise built around recurring Access Stack themes: creation, security, autonomy, systems engineering and the tension between useful technology and control.

The Season One and Awakening studies use a blue-and-white protagonist suit, a red-and-black rival, an Arctic research facility, the fictional Quantum Cipher Security Codes and a ten-episode structure. These are narrative design studies and previsualization, not claims about finished products or real hardware.

The visual archive gives this work a dedicated home alongside aerospace concepts, product-interface studies and research graphics.

PRODUCT CONCEPT / IDENTITY

Access Stack Trust: authenticate once, prove trust cryptographically

The Trust concept asks a practical question: how much repeated password friction can be replaced by device-bound cryptographic proof without weakening security?

The working architecture is grounded in standards that already exist: passkeys and WebAuthn, FIDO2, OAuth and OpenID Connect, SSH keys or certificates, TPM-backed keys, Windows Hello and Linux PAM integration. A trusted device signs challenges while the private key remains inside secure hardware.

This remains an architecture direction rather than a finished authentication service. The useful constraint is that the design starts from established standards instead of inventing a proprietary security mechanism merely for novelty.

PRODUCT CONCEPT / PLATFORM

Relay and the Access API Fabric

Relay is the desktop-facing control-plane direction: one inspectable workspace for routing local and cloud models, agents, telemetry and orchestration without forcing the user into a single provider.

The broader API Fabric concept would give multiple small services a shared operating layer for authentication, rate limits, usage metering, audit logs, routing, retries, webhooks, secret handling and bring-your-own-key support.

Candidate services include a model gateway, repository intelligence, document generation, memory, browser-tab intelligence and notification APIs. Each service has to justify itself through a working use case before it earns a permanent place in the platform.

SYSTEMS / BUILD LOG

Windows installer prepared; installation work remains evidence-driven

The preparation record includes a bootable installer workflow from Ubuntu, verification of the copied Windows image and careful handling of the target disk layout before installation.

The goal is to preserve Ubuntu and existing files while restoring a usable Windows environment for development and project recovery. Disk layout, EFI state and destination partitions are checked before destructive steps rather than relying on stale assumptions.

The journal deliberately distinguishes preparation from verified success: an installer is useful, but the milestone is a working installation with intact data, working drivers and recoverable project files.

SYSTEMS / INVESTIGATION

NVIDIA dependencies: keep the repair evidence

The Ubuntu graphics repair has involved package-version checks, DKMS state, Secure Boot awareness and dependency cleanup. The operating rule is to distinguish a proposed command, a simulated package change and a verified result.

That matters around graphics drivers because package changes can affect the desktop, CUDA tooling and development workflows at the same time.

Final repair notes belong in the public record only after the installed version, kernel-module state and working GPU output agree.

STUDIO / PLANNING

Turning Access Stack into a focused independent studio

Access Stack brings together software projects, systems experiments, research and visual design. The business direction is to make that work understandable enough that another person can evaluate what exists, what is being developed and what could become a commercial product.

The practical path is deliberately staged: recover and consolidate the strongest existing projects, select a flagship commercial product, validate demand, then expand infrastructure and services as the evidence supports it.

Research projects and visual concepts remain part of the studio, with status labels kept explicit so production software, prototypes, experiments and design studies do not blur into one another.
