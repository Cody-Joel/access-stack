RESEARCH SYSTEMS

Different failure modes require different instruments.

Access-Stack is organized around focused evaluation systems rather than one catch-all benchmark.

01

BEHAVIORAL EVALUATION

SpecStack

Runs the same value-conflict scenarios under bare-rule and explained-value conditions, then measures behavioral divergence between them.

  • Controlled prompt conditions
  • Cross-model comparison
  • Behavioral divergence analysis
02

MONITOR RELIABILITY

SentinelBench

Tests whether AI monitors detect harmful behavior when the signal is subtle, stateful, or dependent on careful artifact tracking.

  • Synthetic adversarial transcripts
  • Overt vs. subtle comparison
  • Monitor blind-spot analysis
03

HUMAN SKILL RETENTION

SkillStack

Compares AI-assisted and solo coding conditions, then tests conceptual retention rather than measuring completion speed alone.

  • Assisted vs. solo conditions
  • Conceptual follow-up testing
  • Retention-focused evaluation

PILOT FINDINGS

Signals worth scaling, not conclusions dressed up as certainty.

3 → 0

Three models changed position on one contested scenario after the values were explained.

In the “business idea with serious flaws” pilot scenario, three of five model families shifted from softening the answer to leading with the direct assessment. With value explanations, all five selected the direct-first response.

CONTROL Clear cases stayed stable.

On an explicit deception scenario, all five models chose the honest response in both conditions.

AMBIGUITY More explanation did not resolve every tradeoff.

On a genuinely underspecified thesis scenario, model choices still diverged.

MONITORING Subtle harmful actions were harder to catch.

SentinelBench pilots showed stronger detection of overt harm than state-tracking and locale-dependent failures.

Current results are pilot-scale. Access-Stack explicitly treats them as preliminary signals that need larger samples, repeated runs, and stronger statistical validation.

OPERATING PRINCIPLES

Useful security and AI research depends on disciplined boundaries.

01

Authorized defensive scope

Security work is intended for systems, applications, networks, and data that are owned or explicitly authorized for assessment.

02

Evidence over theatre

Small studies are labeled small. Limitations stay visible. Claims should track what the data can actually support.

03

Secrets stay out of source

API credentials belong in environment configuration, not committed source code or public repositories.

04

Human-readable systems

Raw outputs, configs, and findings remain inspectable so the research can be reproduced and challenged.
